# Secret Manager mounts of the production web server (Cloud Run john-bogle-ui):
# ENV_NAME=secret-name:latest. Keep sorted, one per line. The workflow joins
# the lines with commas into --set-secrets, which REPLACES the service's
# secrets on every deploy.
#
# The service runs as john-bogle-ui@, which has secretAccessor on each secret
# listed here and nothing else: a new line needs that grant too, or the deploy
# fails. A secret with no enabled version also fails the deploy
# ("…/versions/latest was not found", #1721).
#
# DISPATCH_SIGNING_SECRET signs the calls this server places (proactive
# check-ins, on-behalf, family check-ins); the voice agent verifies with the
# same secret (#1706). This repo is public: who gets proactive check-ins
# (PROACTIVE_CHANNELS_USERS, Firebase uids) comes from the
# proactive-channels-users secret, never env.yaml or the workflow.
#
# APNS_* send pushes to the iPhone app straight to Apple (token auth, .p8 key);
# SIWA_* revoke a Sign in with Apple grant when that person deletes their
# account. Both do nothing until the code that reads them ships; IOS_PUSH
# stays off per person.
#
# DATA_ENCRYPTION_KEY and IDENTIFIER_HASH_SECRET are privacy-crypto's keys
# (smart-home credentials, developer MCP servers, OAuth clients): without them
# every privacy-crypto call throws in production. The voice agent reads what
# this server seals and hashes, so it holds the same two secrets.
