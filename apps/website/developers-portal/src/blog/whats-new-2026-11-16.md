We have landed several updates across Ferni to improve data safety, clean up session tracking, and keep our developer tools sharp. Here is what merged recently and why it matters for your work.

## Session tracking and time zones

Session counts across prompts, past chats, and journey panels used to disagree. [#2149](https://github.com/ferni-ai/voiceai/pull/2149) landed to create a single source of truth based on completed calls where someone spoke. This ensures consistent counts across backend calls and client screens.

Web time zone caching landed in [#3779](https://github.com/ferni-ai/voiceai/pull/3779). The web application used to cache local time zones before confirming server updates. Now it caches the zone only after the server accepts the sync. If a sync fails or gets skipped, the web app retries on the next start so quiet hours and outreach land at the right local hour.

## Data protection and account erasure

Account deletion safety landed in [#2885](https://github.com/ferni-ai/voiceai/pull/2885). Previously, if an erasure step failed, the app could still delete the sign-in account, leaving behind uncleaned data. Now, if any cleanup step leaves data behind, the request fails and keeps the sign-in open so people can safely retry.

To help monitor data cleanup, [#2902](https://github.com/ferni-ai/voiceai/pull/2902) landed a read-only audit tool that counts records left behind by incomplete account erasures. A follow-up test fix landed in [#2945](https://github.com/ferni-ai/voiceai/pull/2945) to pin the orphan audit to the database named by the environment flag.

Spoken credential redaction landed in [#2456](https://github.com/ferni-ai/voiceai/pull/2456). Free-text memory redaction now catches spoken PINs, passwords, front door codes, and security answers. This keeps sensitive personal secrets out of stored memory facts.

Smart home credential handling landed in [#2918](https://github.com/ferni-ai/voiceai/pull/2918). Save operations now fail closed on read errors so transient failures will not wipe stored credentials. In addition, sealed credential fields inside route envelopes decrypt properly bound to the field and person.

Privacy policy updates landed in [#2953](https://github.com/ferni-ai/voiceai/pull/2953). The website content was updated to match iOS 1.0, reflecting the minimum age of 18, Sentry crash reporting details, data provider listings, and in-app account deletion instructions.

## Integrations and tooling

Fitbit integration removal landed in [#3118](https://github.com/ferni-ai/voiceai/pull/3118). Google is shutting down the legacy Fitbit Web API, so we removed the Fitbit provider, OAuth routes, status settings, and locale strings to prevent broken connection buttons.

Evaluation tooling landed in [#2495](https://github.com/ferni-ai/voiceai/pull/2495). Seth needed a way to score turn reading rules, so we merged an offline evaluation script that tests turn readings against the golden set dataset.

Waitlist management landed in [#2043](https://github.com/ferni-ai/voiceai/pull/2043). The waitlist command-line tool allows dry runs and handles wave 0 onboarding for existing signed-in accounts and pending invites.

## CI checks and interface contrast

Continuous integration guardrails landed in [#2319](https://github.com/ferni-ai/voiceai/pull/2319). A new check flags added lines that turn off test steps or soften error handling, keeping automated gates reliable.

Home resting line contrast landed in [#2967](https://github.com/ferni-ai/voiceai/pull/2967). We adjusted the resting line rendering on iOS so text meets contrast requirements under accessibility audits without changing base design tokens.
