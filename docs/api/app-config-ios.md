# GET /api/app-config/ios

The iPhone app's minimum build and its crisis-mode switch. Public: no auth, no user data.

## Response (200)

```json
{ "minimumBuild": 1234, "message": "A newer Ferni is out. Please update.", "crisisMode": true }
```

| Field | Type | Meaning |
|---|---|---|
| `minimumBuild` | integer or `null` | Builds below this should ask the person to update. `null`: no minimum. |
| `message` | string or `null` | Optional one-line text for that prompt. |
| `crisisMode` | boolean | Whether the app's crisis mode is on (988 up front on the call screen, a calm goodbye, no celebration, reacting only to the server's crisis signals). `true` unless switched off. |

Values come from the environment of the API server, read on each request:

| Env var | Accepted | Otherwise |
|---|---|---|
| `IOS_MIN_BUILD` | a positive whole number, at most 9 digits (`"1234"`; surrounding spaces ok) | `null` |
| `IOS_MIN_BUILD_MESSAGE` | any text; control characters and runs of whitespace become one space; cut at 280 characters | `null` if blank |
| `IOS_CRISIS_MODE` | `off` (surrounding spaces and any case ok) makes `crisisMode` `false` | `true` |

Unset, empty, `0`, negative, decimal, `1e3`, hex or any other malformed value reads as
`null`. The route never answers an error for bad config.

The fields are independent: a message with no valid minimum is returned as is, and
a bad minimum does not drop the message.

## Crisis-mode kill switch

Crisis mode ships on in the app (decided 2026-10-26). iOS has no other remote flags, so
`IOS_CRISIS_MODE=off` is how it is turned off without an app update if false alarms show
up. It fails safe: unset, `on`, `false`, `0`, a typo or any value other than `off` keeps
`crisisMode` `true`, so a misconfigured switch never takes the safety UI away. Prod needs
no value for the default.

## Cache

`Cache-Control: public, max-age=300, s-maxage=300`: five minutes for the app and for any
CDN in front. A change to the env vars therefore takes up to five minutes to reach phones.

## Client rule

Never block on this route. Hold a build only when the response arrived, `minimumBuild`
is not `null`, and the running build number is below it. A timeout, an error, a non-200
or `null` means carry on as normal. It can force an update; apart from `crisisMode` it
never reveals or hides UI. For `crisisMode`, a missing field, a failed request or a
non-boolean means keep crisis mode on; only an explicit `false` turns it off. Older app
builds ignore the field.

## Only GET

Any other method or path under `/api/app-config/` is not handled here (404).

## Where it lives

- `src/api/app-config-ios.ts`, mounted in `src/servers/api/index.ts` just before the
  health routes (after the global per-IP API rate limit).
- Tests: `src/api/__tests__/app-config-ios.test.ts`.
- All three env var names are in `src/config/env-read-names.generated.ts` (generated by `pnpm gen:lists`).
