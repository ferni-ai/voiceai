# Comms Glossary: Contact and Follow-Through

One shared language for how Ferni and the team contact people and follow through on what
they said they would do. Use these words in code, docs, PRs and reviews.

Today one idea often has several types, for example five `Commitment` interfaces and seven
`OutreachChannel` unions with seven different value sets. Later PRs merge them one at a
time into the canonical type named below. This doc only names things; it changes no
runtime behaviour.

- **Check:** `pnpm quality:comms-types` lists every comms type name exported from more than
  one file in `src/` (see [Checking for duplicates](#checking-for-duplicates)).
- **Allowlist:** the names the check watches live in ONE place, `COMMS_TYPE_NAMES` in
  `scripts/check-comms-types.ts`.

Words that look like comms but are not on the list:

- **Channel** is a homonym in this codebase (pub/sub channels, brand channels, delivery
  channels), so the bare name is not watched. The comms meaning is `EngagementChannel` in
  `src/services/conversation-thread/types.ts`: `voice`, `sms`, `email`, `push`, `in_app`,
  `call`.
- **Commitment** and **promise** are kinds of Follow-up, not nouns of their own.

## Rules

1. **Only a proactive touch counts toward the contact budget.** A touch Ferni starts
   (`initiation: 'proactive'`) spends budget once it leaves (`sent`, `delivered`,
   `replied`, `no_answer`, `bounced`). A `held` touch never spends. A reply, or a touch the
   person asked for (`requested`), never spends.
2. **Safety touches never count, and are never held for budget or quiet hours.** Crisis
   resources and 988/911 go out at any hour, whatever the budget. A safety touch is never
   `proactive`, and its `heldReason` is never `budget` or `quiet_hours`.
3. **A touch row never holds message text.** It records who, when, which channel, why and
   what happened. The words stay on the thread, under the thread's own retention.

## Checking for duplicates

```bash
pnpm quality:comms-types           # print the count and every declaring file:line; exit 0
pnpm quality:comms-types --max 30  # exit 1 when more than 30 names are duplicated
```

The check is report-only: no workflow runs it yet. `--max` is there for a later ratchet,
where CI holds the count at or below today's number and each merge PR lowers it.

A declaration is a top-level exported `type`, `interface` or `enum`. Imports, re-exports
(`export { X }`, `export type { X } from`) and non-exported types do not count. Same-named
types inside one file count once.

To add a name, add it to `COMMS_TYPE_NAMES` in `scripts/check-comms-types.ts`, and add a
row here if it is already duplicated.
